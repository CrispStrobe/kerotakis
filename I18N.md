# Languages

Every place a language lives, what it costs to add one, and why each
surface is shaped the way it is.

The organising rule is **one language, one set of files nobody else
touches**. It is not tidiness: it is what lets a French translation and a
Japanese translation be worked on at the same time without their authors
colliding on every commit. Before this rule was applied, three of the four
surfaces were shared mutable files and two translators would have
conflicted constantly.

The second rule is **fall back per string, never per language**. A
half-translated bundle renders half in that language and half in English,
rather than nothing. That is what lets a translation ship while it is
still being written — and it is also the failure mode to watch, because a
string nobody asked for looks exactly like a string nobody translated.
See *How this went wrong, five times* at the end.

## The surfaces

| 1 | Interface | `web/app/src/locales/<code>.json` | 1584 | one new file |
| 2 | Catalogue | `codex/i18n/<code>.toml` | 1095 | one new file |
| 3 | Engine prose | `crates/kerotakis-core/i18n/<code>.toml` | 217 + 193 | one new file + one registry line |
| 4 | Store & PWA | `web/manifest.<code>.webmanifest`, `web/privacy.<code>.html` | — | one new file each |
| 5 | Command grammar | `crates/kerotakis-core/i18n/<code>.toml`, `[script-*]` | 69 rows | the same file as 3 |
| 6 | Curiosity corpus | `tests/coverage/curiosity-v1/i18n/<code>.toml` | 500 + 186 + 367 | one new file |
| 7 | Lesson prose | `lessons/prose/<code>.toml` | 413 | one new file |
| 8 | Console page | `web/index.html`, `BUNDLES` | 51 | one new key in that object |
| 9 | Material aliases | `crates/kerotakis-registry-export/src/lib.rs` | 116 sites | **German only — see the 2026-09-23 findings below** |

The eighth and ninth were found by adding French on 2026-09-23 and are
listed because they were being met and not mentioned. The console page is
the terminal at `/`, which had one inline German dictionary and no file of
its own; it now takes a key per language in the same place. The ninth is
not yet addable at all.

The seventh is the newest (I18N-9). A lesson's title, description, section
comments and boundary note are the `.lab` file's own `#` comments, and they
were rendered verbatim — a German learner met a German lesson name above
six English lines. A LABELLED comment (`#@intro …`) names the place its
prose is said, the catalogue answers for that label, and the `.lab` keeps
the English inline as the per-key fallback. It is still a `#` comment, so
`kero run lessons/x.lab` is unchanged and a `.lab` stays runnable on its
own. `tools/lessons-index.py` compiles the catalogue into the payload's
`lessons/prose.json`; `tools/lesson-prose-lint.py` counts against every
label a `.lab` REFERENCES, never the catalogue's own key count.

The fifth is the odd one: every other surface translates what the bench
**says**, and this one translates what a learner **types**. It lives in
the engine-prose file because a translator who has written German for the
substances has already written most of it — the parser reads `[species]`
and `[glassware]` backwards rather than asking for those names twice.

**No surface shares a file between languages.** A French translator and a
Japanese one can work at the same time and never touch the same bytes.

Start from `web/app/src/locales/_template.json`, which carries every key
with an empty value. It is kept complete against German by
`localeBundles.test.ts` — it was once 122 keys short, and those strings
were not merely untranslated, they were invisible to anyone starting a
language.

### Adding a language, end to end

Five files and one line of Rust. Nothing else, and no existing translation
is touched — which is the property that lets two languages be worked on at
the same time.

| # | Do this | Where |
|---|---------|-------|
| 1 | Copy `_template.json` → `<code>.json`, translate the values, set `@@locale` | `web/app/src/locales/` |
| 2 | Copy `de.toml` → `<code>.toml`, translate the values | `codex/i18n/` |
| 3 | Copy `de.toml` → `<code>.toml`, translate the values — **including the `[script-*]` sections**, which are the words a learner may type | `crates/kerotakis-core/i18n/` |
| 4 | Add `("<code>", include_str!("../i18n/<code>.toml"))` to `CATALOGUES` | `crates/kerotakis-core/src/i18n.rs` |
| 5 | Copy the manifest and the privacy page | `web/manifest.<code>.webmanifest`, `web/privacy.<code>.html` |
| 6 | Copy `de.toml` → `<code>.toml`, translate the values | `tests/coverage/curiosity-v1/i18n/` |
| 7 | Copy `en.toml` → `<code>.toml`, translate the values | `lessons/prose/` |

Step 4 is the only change in the ENGINE, and it is one line. The parser,
the command bar, the refusals and the hints all read whatever the new file
holds: there is no list of languages in Rust, and no language's words are
written there.

### What adding French actually found, 2026-09-23

The table above was a claim, and the only way to test a claim like that is
to add a language. French was added, and **four places had to be edited
that the table does not mention.** Each is now generalised, so the next
language does not meet them — which is the whole return on the exercise.

| Where | What it was | What it is now |
|---|---|---|
| `web/index.html` | `startsWith("de")` chose the manifest | a `shipped` list; the code picks its own manifest |
| `web/index.html` | `const DE = {…}`, the console page's ONLY dictionary | `const BUNDLES = { de: …, fr: … }`, keyed by code |
| `tools/build-web.sh` | copied `privacy.de.html` and `manifest.de.webmanifest` by name | copies `privacy.*.html` and `manifest.*.webmanifest` by glob |
| `tools/console-locale-lint.py` | parsed the page by `page.index("const DE = {")` | reads every `<code>: {` in `BUNDLES` |

The last one is the one worth staring at: **the lint that exists to check
this surface was itself German-only**, and it did not report a gap when a
second language arrived — it crashed. A gate hardcoded to the thing it
gates is not a gate.

The build-script one is the quietest. Forgetting it does not fail
anything: it ships a language whose install prompt and privacy page are
simply absent, in a build that is otherwise green.

**What held, and is worth saying because it was not obvious.** `Locale` is
a newtype over the `CATALOGUES` table rather than an enum, so the engine
took a third language without a single match arm changing. `Codex::load_dir`
reads every `*.toml` in `i18n/` by filename. The codex structs carry
`#[serde(flatten)] other_locales` beside their `*_de` fields, so a French
sidecar key lands and serialises back out as `question_fr` with no field
declared for it. `availableLocales()` is built from the bundles, so French
appeared in the picker — with `Français` as its accessible name — from
adding one file and nothing else. Every lint reported French rather than
failing on it, because `COMPLETE` is a set and French is not in it.

**One surface remains German-only and is not fixed here:** material
aliases. `kerotakis-registry-export` builds recipes through a closure
taking `de_aliases: &[&str]`, and the alias map is written
`("de".to_string(), …)` at 116 sites. A French translator cannot give
`Leitungswasser` a French name without editing Rust. That is a
data-shape change rather than a plumbing one — the parameter has to become
a map of code to aliases — so it is recorded here rather than done badly.

Then run the gates: `cargo test -p kerotakis-core` (the coverage gate walks
the engine's own registries and fails on a term the new file lacks),
`npm test` in `web/app` (the bundle gate), and
`python3 tools/engine-locale-lint.py --check`.

### Two hosts, and only one of them used to speak German

The engine is reached through **two** bindings, and translating one does
nothing for the other:

| Host | Binding | Used by |
|------|---------|---------|
| wasm | `crates/kerotakis-wasm/src/lib.rs` | the browser and the PWA |
| native | `web/app/src-tauri/src/lib.rs` | **everything on the App Store** — iOS and macOS |

For as long as the engine had a catalogue, the native binding imported the
English-only `render_events` / `render_vessel`, had no `set_locale`
command, and did not contain the word `locale`. So the entire engine
translation applied to the browser and to nothing else: German buttons
around English prose, on the device people actually use.

Nothing reported it, because `Session.connect` wrapped the refused
`set_locale` in a `catch`. Both bindings now render through
`render_events_in` / `render_vessel_in` and call `localize_events`, and
`every_command_the_shell_sends_is_answered` scrapes `TauriHost.ts` and
fails if the native side cannot answer something the shell sends.

## 1. The interface — `web/app/src/locales/`

One JSON bundle per language, discovered by filename with `import.meta.glob`.
Nothing imports them individually, so **adding a language is adding a file**.

```json
{
  "@@locale": "fr",
  "terms":    { "water": "eau", ... },
  "messages": { "the bench": "la paillasse", ... }
}
```

- `terms` — the engine's vocabulary: species, colours, hazards. Substituted
  inside longer sentences.
- `messages` — the interface's own strings, plus the concept labels and
  experiment names the codex refers to by slug.
- Keys are **the English source text**, because that is what `t()` is
  called with. Values only are translated; a changed key silently orphans
  its translation.
- Bundles are inlined at build time. A language fetched over the network is
  a language you cannot read on a train, and this app is offline-first.

**To add one:** copy `_template.json` (all keys, empty values) to
`<code>.json`, set `@@locale`, translate the values. No code change.

`availableLocales()` reports what a build actually ships. `_template.json`
is skipped, so it is never offered as a language nobody can read.

## 2. The catalogue — `codex/i18n/<code>.toml`

The 103 experiments are English in `codex/*.toml`. Every translation lives
in a sidecar, one file per language, keyed by the path to the English field
it translates:

```toml
"strong-base.registers.lv1" = "Diese Flüssigkeit ist das Gegenteil einer Säure…"
"strong-base.expect.predict.question" = "Was wird das pH-Meter anzeigen?"
"strong-base.expect.predict.options" = ["3", "7 — Hydroxid ist keine Säure…", "11"]
"strong-base.expect.predict.diagnosis.0.reveals" = "…"
```

Array indices are path segments. `Codex::load_dir` folds them in, writing
each value into the `_<code>` sibling the structs and the export use — so
nothing downstream knows the translation came from another file.

**A key translating nothing is an error, not a spare.** It means the
English moved and the translation is left describing what is gone, which
renders confidently and wrongly. That is not hypothetical: while this was
being built, `rates.toml` carried German claiming the engine could not
stir, months after it learned to.

`options` deserves care. It is a positional array, and the catalogue stores
the correct answer as an INDEX into it with each diagnosis attached by
index — so a translation of a different length marks the wrong answer
correct and explains a belief the learner never expressed. The UI treats a
mismatched array as absent rather than indexing into it.

**To add one:** copy `codex/i18n/de.toml` to `<code>.toml` and translate the
values. Keys are paths and must not change. No code change.

`tools/codex-locale-lint.py --check` is the gate, and it runs in
`preflight.sh`. It reports coverage per language and per source file, and
it FAILS on four things: a stale key, a list whose translation changed
length, an age band or children's-audience wording (GUI-470 — this prose
never reaches the locale bundles, so `learnerWording.test.ts` cannot see
it), and — for a language in `COMPLETE` — any missing string.

`COMPLETE` is the distinction that makes both halves work. German is in it,
so a new catalogue entry fails preflight until it is translated. A language
NOT in it is only reported on, so a French translation can be committed
five strings at a time and grown, which is the whole point of falling back
per string. A language joins `COMPLETE` when its author says it ships.

### The models half was dark for a year

`models.toml` reported **100% German** while 325 of its 409 learner-facing
strings rendered in English. Two independent causes, and either alone would
have been enough:

- The lint's `TRANSLATABLE` list named only `lv1`/`lv2`/`lv3` for a model,
  so the denominator was 84 rather than 409. A field nobody counts cannot
  be reported missing, and `fails_at` — the stated boundary, the field a
  model exists for — was never once counted as untranslated.
- `Model` had no `name_de`, `power_de`, `explains_de` or `fails_at_de` and
  no `other_locales` map. A sidecar key for one of them injected into the
  TOML document correctly and was then **silently dropped by serde** on the
  way into the struct, because no field claimed it. This is exactly the
  French-half-appears bug described above, except that it applied to German
  and nobody had written the German yet, so it never fired.

Both are fixed. The lesson is the general one: **a coverage number is only
as honest as its denominator**, and a denominator written by hand will
drift from the schema it claims to measure. `test_codex_locale_lint.py`
now asserts that the four model fields are in `TRANSLATABLE`, so removing
one fails a test rather than quietly improving the percentage.

Note that the models are exported but **not yet rendered**: `parseCodexIndex`
in `web/app/src/lib/codex.ts` keeps `doc.reactions` and drops `models` and
`concepts`. The German is therefore correct and ready rather than visible,
which is the right order — a renderer added later reads a translated
catalogue instead of shipping English.

That last sentence was untrue for a while, and the way it was untrue is
worth keeping. `Registers` is a map, so `lv1_fr` travelled fine. The prose
fields are not maps — `summary_de`, `question_de`, `reveals_de` and five
others are *named struct fields*. A French sidecar therefore parsed without
complaint, injected `summary_fr` into the document, and serde dropped it on
the way into the struct because no field claimed it. French would have
half-appeared: level prose translated, summaries and predictions silently
English.

Each of those structs now carries a flattened `other_locales` map that
catches what the named fields do not and serialises it back out, so
`summary_fr` reaches the JSON the shell reads and `tEngine` finds it
there. German keeps its typed fields, so the German path and the golden
snapshot are untouched — a German-only catalogue leaves the map empty.

`crates/kerotakis-codex/tests/french_probe.rs` holds the claim to account:
it writes an English file and an `i18n/fr.toml` into a temporary directory,
loads them the way the CLI does, and requires the French in the exported
JSON. French is used because it is the cheapest language that is *not* the
one the types were written for — German proves nothing here, being the
language every field is named after.

## 3. The engine's own prose — `crates/kerotakis-core/i18n/`

The vessel summary and the journal are composed in Rust out of fragments,
so no amount of catalogue data can reach them. `Locale` lives beside
`Register`: the register says how *much* to say, the locale says in *what
language*, and they are the same kind of decision about the same sentence.
It belongs to the engine because every host renders the same line — if the
CLI, the web app and the Mac app each translated for themselves they would
drift into three vocabularies, and PROTOCOL.md's rule that the UI must not
be able to tell the transports apart covers the words as much as the
numbers.

Call sites read:

```rust
locale.t("vessel.open", ", open to atmosphere")
```

The English stays inline: it is the source text, it keeps the line legible
without opening another file, and it is the fallback. A key missing from a
catalogue renders English — never a blank, never the key.

Keys name **a place, not a phrase** — `vessel.open`, not
`open-to-atmosphere` — so rewording the English does not orphan every
translation of it.

**To add one:** copy `i18n/de.toml` to `i18n/<code>.toml`, translate the
values, add one line to `CATALOGUES` in `src/i18n.rs`.

This surface used to be `locale.say(en, de)`, which took both languages as
arguments and therefore **could not express a third at all** without
changing every call site. That is why it was replaced before anything else.

### Nothing is still English here

    engine prose in render.rs
       reachable by a catalogue :  615 keys
       still inside a bare format!:   0 literals
    bench refusals in bench.rs
       reachable by a catalogue :   19 keys
    sentences the engine composes
       reachable by a catalogue :  177 keys

    de                  634 / 634   100.0%   (+614 looked up by value)

Every sentence the engine composes goes through the catalogue — including,
since I18N-7 and I18N-8, the ones it ASSEMBLES rather than writes down
(see 3a). The "+614 looked up by value" are the tables — species,
glassware, instruments, phases, phase-change verbs — where the English
name is the lookup key, so an untranslated one reads in English inside a
German sentence rather than vanishing.

**This file used to say something else here, and it was wrong.** Until
I18N-13 the count read *27 literals*, and this paragraph defended them:
they were "LV3 evidence lines for a reader who asked for the working,
counted separately on purpose." That exemption is withdrawn. LV3 is a
REGISTER A READER SELECTS — the same reader, the same session, one
setting along from LV2 — and not a debug mode. The standing requirement
is that i18n covers every user-facing string and does it modularly, and a
register a reader can choose is a user-facing string. Twenty-seven lines
that stopped at the language boundary were twenty-seven places where
choosing "show me the working" also chose "and read it in English".

The exemption also cost more than the lines it excused. `{method}` — the
hole `chromatographed.lv3` grew to say whether a partition coefficient was
computed or reviewed — could not reach a German reader at all, because the
German row still had the old clause written into it where the hole
belonged. An exemption is not inert: it is a place where drift is not
looked at.

**And the count itself was short.** `engine-locale-lint.py` found prose by
looking for two adjacent English words, which is the right threshold for a
scanner that reads every literal in the file — it has to not report
`, &vessel.to_string()), (`, the text BETWEEN two strings on one line, as
English. The cost is a sentence whose words are all separated by holes:
`"{vessel}: {reaction} released {energy_j:.2} J"` carries exactly one
English word and no two of its words are adjacent.

Fifteen lines lived in that gap — one at LV1, one at LV2, the rest LV3 —
while the file reported them as nothing at all. A `format!`'s first
argument is a TEMPLATE by construction and never code, so it can be judged
on its own terms: blank the holes, and one English word is enough. The
lint does that now, in addition to the old scan, and the true starting
number was **45** rather than 27:

| measured against | `origin/main` | after the 27 | after all 45 |
|---|---|---|---|
| the old scan | 27 | 0 | 0 |
| the scan that also reads templates | 45 | 15 | **0** |

This is #505's shape in its purest form — the instrument could not see a
surface, so the surface did not exist — and it is why the exemption could
sit here for as long as it did looking like a small one.

Two shapes were worth naming while getting there, because both will recur:

**English grammar compiled into a format string.** `"the {} jump{} to it"`
with `if n == 1 { "s" } else { "" }` inflects an English verb by appending
a letter; German changes the whole word (springt/springen). Any
`if …{ "word" } else { "other" }` inside a format argument is English
leaking into the code, and the fix is that the CASE selects the KEY, with
each key holding a complete sentence.

**A hole named after its position rather than its quantity.** `{}` says
nothing about what goes in it, and a translator cannot reorder holes they
cannot tell apart. The same expression can mean different things in
different sentences: `strongest * 100.0` is `{travelled}` in the line about
how far particles got down the tube, and `{separation}` in the line about
how well they separated.

### Measured, not assumed

The claim above was tested rather than argued. A throwaway French
catalogue of five keys was dropped in and one line added to `CATALOGUES`;
the engine rendered:

```
v1 (bécher) — 25,00 °C, 0,0 g, 0,0 mL liquide, ouvert à l'atmosphère
```

Five translated keys, everything else falling back to English per key —
which is the behaviour that lets a translation ship before it is finished.
The probe was then removed: shipping a five-key French would offer a
language that is not there.

The only thing the probe broke was a unit test asserting `"fr"` is an
unknown tag. It now uses `zz`, which is reserved and will never be a
language, so adding French later fails nothing.

### What is left of the shell's translation layer

`web/app/src/lib/engineText.ts` used to translate the engine's prose in the
shell, by regex-matching the English the Rust renderer emits. It predates
the engine catalogue. Now that `render.rs` carries its own 217 keys, almost
all of it is dead — a pattern matching English can never fire on a line the
engine already rendered in German — and the dead patterns have been
removed. It is down from 90 lines to 36, and from fifteen hardcoded German
strings to one.

**Nothing remains in the shell.** The hazard notes were the last holdout,
and they were last for a structural reason: `Feed.svelte` reads `hazard`
and `real_world` straight off the serialised event rather than through
`render_event_in`, so no catalogue on the Rust side could reach them. They
were translated in the shell or not at all, and for a long while they were
not — a German frame around English prose, in the one place where going
unread is dangerous rather than untidy.

`localize_events` in the wasm wrapper now translates them on the way out,
at the first point that knows the language. `bench.rs` and the safety
screen cannot do it themselves: they have no locale, and should not.

The shell's version is worth remembering as an argument against ever
putting a translation there. It built a German compound by appending
`dampf` to a translated species name — `ethanol → Ethanol → Ethanoldampf`.
The substances that actually reach that sentence are formulas: NH3, Cl2,
SO2, NO2, NH2Cl and methanol. German hyphenates a formula onto a noun
(*NH3-Dampf*, never *NH3dampf*), and Cl2, SO2 and NO2 are gases rather
than vapours. The shell got both wrong, and no pattern over the English
could have got them right. The sentences are written out instead, and
`hazardous_vapours_are_all_translated` walks `senses::ODORS` so that
adding a hazardous substance without German fails a test rather than
shipping silently. It caught NH2Cl the first time it ran.

**`engineText.ts` is now a passthrough**, kept only so its call sites need
not all change at once. Do not put a translation back into it. A German
string written in the shell is not a missing translation, it is one that
only German can ever have — there is nowhere to put French.

### The bench's refusals

`bench.rs` composes the reason a refusal gives — "nothing to evaporate — no
water in the vessel" — and carries it in the event as English. The frame
around it was already translated, so a German learner read

    v1: noch nicht modelliert — nothing to evaporate — no water in the vessel

Those reasons are now looked up by their English text, the same way species
and instrument names are, and fixed reasons are translated as complete
sentences.

Reasons with a species inserted into them are localised before they cross
the host boundary. `localize_event` recognises the engine's structured
reason shapes, translates the species through the same catalogue as the
journal, and fills a complete sentence in the selected language. Fixed
meter refusals remain exact catalogue entries. Unknown reason shapes still
fall back intact rather than disappearing.

### The bench's ERRORS — a different problem, and a different fix

The paragraphs above are about `Event::NotYetModeled`, where the bench did
something and reports a gap in the model. `BenchError` is the other kind:
the bench did **nothing**, and says why. `no vessel v2`, `amount must be
positive`, `the last vessel must stay on the bench`.

These were not untranslated. They were **untranslatable**, and the
distinction is the whole lesson of this section. Each arm carried its
sentence in a `thiserror` attribute:

```rust
#[error("no vessel {0} — make it first with `new`, which creates the next free vessel")]
NoSuchVessel(VesselId),
```

Both hosts called `to_string()` on it and threw the result at the shell. By
the time anything knew the reader's language, the words had been chosen and
the values baked into them: there was no key for a catalogue to answer, and
therefore nothing for a coverage gate to report missing. Every i18n gate in
the repo was green over all eighteen of them, truthfully — the coverage was
measured over the keys that existed.

The fix is the same shape events already had. A refusal is a **key**, the
**English source text** with named holes, and the **values**:

```rust
Refusal::new(
    "error.no-such-vessel",
    "no vessel {vessel} — make it first with `new`, which creates the next free vessel",
)
.with("vessel", v)
```

`Display` for `BenchError` is `render(Locale::EN)` over that same template,
so **the English is generated, not copied**. A CLI user, a log line and
every golden fixture see the byte-identical sentence they saw before, and
there is no second copy to drift.
`refusal_locale.rs::the_english_is_exactly_what_it_was` pins all eighteen.

Where the language is chosen matters as much as the shape. It is chosen at
the host boundary — `e.localize(self.locale)` in `kerotakis-wasm`, in
`src-tauri`, and in the CLI's `run_op` — for the same reason
`localize_events` chooses it there: **that is the first point in the stack
that knows.** `bench.rs` does not, and should not; a bench that had to be
told a language in order to refuse would carry the reader's locale through
every solver.

Two hosts, again. `both_bindings_localize_the_refusal_rather_than_stringify_it`
scrapes both files, because "the engine's whole catalogue applied to the
browser and to nothing else" is the mistake this codebase has already
made once, and the refusal path has exactly the same shape.

| | before | after |
|---|---:|---:|
| refusals with a key | 0 | 18 |
| refusals with German | 0 | 16 + 2 pass-through |
| gated so a new one fails | no | `i18n_coverage.rs` |

The two pass-throughs are `IntegrationError` and `TransportError`, which
still write their own English one layer down. They have a key
(`error.kinetics`, `error.transport`) whose German is `{detail}` — a frame
waiting for the day those types get keys of their own, and honest about
being one.

**Adding French to the refusals is one row per key in `fr.toml`.** No Rust.

### What the English-keyed table cannot reach

`[refusal]` is keyed by the whole English sentence, because that is what
`Event::NotYetModeled` has in hand: the reason travels in the event as
finished prose. That works for a reason which interpolates nothing, and it
cannot work for one that does — the key would have to contain the value.

The engine writes **57** of these, in seven files. **18** are fixed strings
and **39** are built with `format!`. Until this pass, five of the eighteen
had German, and the table reported itself complete because a percentage is
computed over the rows that exist. Thirteen fixed reasons — the volume
meter, the hydrometer on an empty vessel, both chromatography refusals, the
titration one, `cooling an empty vessel` (a copy of `heating an empty
vessel` with one word changed and no row of its own) — reached a German
learner in English with every gate green.

`every_fixed_gap_reason_has_german` now scrapes `what: "…".to_string()` out
of the six core sources and requires German for each. Same trick as the
refusal gate, same reason: the inventory has to come from the code that
writes the sentence, or it goes stale on the commit that needed it.

The other **39 need the wire-format change**, and that change is blocked on
something worth writing down. Adding a `refusal: Option<Refusal>` field to
`Event::NotYetModeled` — additive, `serde(default)`, so every saved log and
golden fixture still replays — would be the whole fix. But a struct variant
requires every field at every construction site, and **seven of those sites
are in `crates/kerotakis-phreeqc/src/aqueous.rs`**, which is another
session's file. There is no Rust shape that adds a field to a struct
variant without touching its constructors, so this is a coordination
problem rather than a design one.

For that crate's owner, the seven are at `aqueous.rs` lines 3565, 3620,
3677, 3687, 3767, 3796 and 3855 — all `format!`, all English today.

### The hazard sentences, and the hole beside the table

`every_incompatibility_warns_in_german` walks `INCOMPATIBLE`, which is the
right inventory for the nine rules that are rows in it and no inventory at
all for the two that are not. `water-reactive-slaking` and
`liquid-nitrogen-handling` are constructed inline, and the blind spot was
exactly the size of the bug: slaking happened to have German, liquid
nitrogen happened not to, and no test could tell them apart.

`every_hazard_sentence_in_this_file_has_german` reads the `hazard:` and
`real_world:` literals out of the source instead, so a sentence written
outside the table is still an inventory of one.

### What is still English, and why

`script.rs` — the parser — answers in English everywhere but one message.
Its errors are `Result<_, String>`: sixty-three sites, thirty-three of them
`usage:` lines, with no type between the `format!` and the caller to hang a
key on. That is a different change from this one (it is a shape change to
the parser, not a wire-format change to an error enum) and it is tracked
separately. The `NotYetModeled` composers were the third such body, and are now a
migration in progress. Most of them interpolate a value and so cannot be
reached by the English-keyed `[refusal]` table at all. The event carries a
`reason: Option<Phrase>` beside `what` — exactly what `Inert` carries, and
this was exactly that defect one event along — and `Event::not_modeled`
generates `what` from it, so the English and the translation are one
sentence rather than two. `None` means a site that has not been converted
yet; it still falls back to `[refusal]`, and
`tools/engine-locale-lint.py` prints how many of each there are with the
denominator read out of the Rust rather than out of a catalogue. See
I18N-10 in `ROADMAP-GUI.md` for the order the remaining tranches go in.

### 3a. The sentences the engine BUILDS — `crate::phrase`

Everything above translates a string that is written down somewhere: a
call site passes `locale.t("vessel.open", ", open to atmosphere")`, and the
English in the Rust is both the source text and the fallback. That shape
covers every line where the ENGINE chose the sentence and only the values
vary.

It does not cover the lines the engine ASSEMBLES, and for a year those were
English in every language while every gate stayed green. `appearance.rs`
built what a vessel looks like out of parts — `format!("there is {list} in
the beaker")`, a `" and "` between the names, a colour word glued in front
of each one — and the solvers built the inert verdicts the same way. There
was no key to miss, so no coverage percentage could count them:

> Du siehst dir v1 genau an. **There is white baking soda (sodium
> bicarbonate) and white citric acid in the beaker.**

The obvious repair does not work. Translating `"there is"`, `" and "` and
the colour separately and gluing the German together fails three different
ways at once:

* **Order.** French puts the colour after the noun — *chlorure d'argent
  blanc*. No translation of the fragments can move them.
* **Inflection.** A German attributive adjective takes the noun's gender —
  *weißes Natron* but *weiße Citronensäure*. "White" is not one word.
* **Connectives.** `", "` and `" and "` are a list GRAMMAR, not two
  strings; some languages use neither.

So the unit of translation is the whole clause with named holes, and the
engine emits the **recipe** rather than the sentence:

```rust
Phrase::new(
    "look.deposit-in-liquid",
    "there is {what} at the bottom",
    vec![("what".to_string(), Slot::List { items: … })],
)
```

`Appearance` carries the clause list beside the English `words` every
existing consumer still reads, and `Appearance::say(locale)` recomposes it
where the host knows who is reading. `Event::Inert` and
`Event::InertInSolvent` carry a `reason: Option<Phrase>` the same way, and
their English `why` is **generated from that phrase** rather than written
next to it — so there is one sentence and not two to drift.

The slot types are the part a flat `fill` could not express:

| Slot | For | In the catalogue |
|---|---|---|
| `Text` | a name or notation — `v1`, `2H⁺/H₂` | never translated |
| `Number` | a value already formatted to the engine's precision | gets the reader's decimal separator |
| `Term` | a species, a material, a colour word | `<section>.<english>` |
| `Phrase` | a clause inside a clause — `{colour} {name}` | its own key |
| `List` | several of the above | joined by `look.list-separator` / `look.list-final` |

Only the composer knows that *silver chloride* is a species and *white* is
an appearance word. By the time a sentence is a string, that is gone and no
catalogue can get it back — which is the whole argument for `Slot` being a
type rather than a `String`.

**Adding a language changes nothing here.** The `[look]` and `[inert]`
sections are rows in the same `<code>.toml` as everything else, and a
translator who needs a different construction writes one: German's
`look.coloured` is `"{name} ({colour})"` because no single translation of
"white" can decline, and the three list-bearing clauses use *du siehst* to
sidestep verb agreement, which is right for one thing and for three. Both
decisions live in the data.

The gate is `crates/kerotakis-core/tests/composed_locale.rs`, and its
denominator is read out of the SOURCE — every `Phrase` key written in a
composer file, plus every row of `nonaqueous::INERT_IN_SOLVENT` — never
out of the catalogue, which is the denominator that let `models.toml`
report 100% German over 325 English strings. A second half observes real
beakers and walks the clause tree, so an untranslated colour word fails as
loudly as a missing key.

#### The scene says it a second time (I18N-11)

Making `appearance.rs` speak German bought a WEB reader nothing, and it
took a second look to see why. The web canvas paints its caption and its
accessibility text from the **scene**, not from the rendered notebook
line — `t(vessel.words)` in `Vessel.svelte` — and `scene_vessel` took the
finished English `words` off the observation and appended its own
`format!`s to it: osmosis, the gel, the swelling, the glow, the enzyme,
the adsorption split, the partition, the emulsion, the layer, the curds,
the foam. Twenty sentences, each one a whole statement rather than a
clause, and the German half of the line stopped exactly where they began.

`SceneVessel` now carries `clauses` (the observation's, passed straight
through) and `notes` (its own), `SceneVessel::say(locale)` recomposes
both, and **`words` is generated from them** rather than written beside
them. `scene::localize(&scene, locale)` does for the scene what
`render::localize_events` does for the events, and the wasm boundary calls
it on the way out — which is the only place that knows who is reading.

Two of those sentences already had German in `web/app/src/locales/de.json`
(the coating films, which have no holes, so a whole-sentence lookup could
reach them). The engine's rows take that German word for word: a second,
different German for one sentence is how one product starts reading like
two.

Note `scene.material-layer`. English writes "olive oil forms a separate
yellow layer above the water"; German cannot, because *gelb* has to
decline to *Schicht* and *orange* and *rosa* do not decline at all. The
German row puts the colour beside the noun — `"… eine eigene Schicht
({colour}) über dem Wasser"` — which is the same decision `look.coloured`
made, taken again in the data and not in the Rust.

#### `Provenance.routing` — the same defect on a field that is not a refusal (#642)

`Inert.why` and `NotYetModeled.what` are the bench declining to claim
something. `Provenance.routing` is the opposite: it is said BESIDE the
numbers, and it says which dataset answered and why. It was welded shut
the same way — a `format!` for the dataset choice, a `push_str` for the
activity-model caveat, a `format!` for the redox note, another `push_str`
for the second speciation, and in `displacement.rs` a whole paragraph
about the electrode pushed onto whatever the aqueous router had already
written. Five writers, one string, no key.

It is a `Phrase` now, and the composition is **nesting** rather than
concatenation: the caveat's template carries `{routing}` as a hole and
puts the clause it qualifies inside itself, so a language that wants the
qualification first writes its row the other way round. `sentence_pair`
joins the electrode sentence to its hydrogen-line caveat, because those
two are whole sentences and neither is a slot in the other.

The thing that made this one different is that **`routing` is not only a
display string.** `tools/chemistry-audit/analyse.py` files it verbatim as
a `routing_claim` beside the numbers it checked; `kero explain` prints it;
three tests in `kerotakis-phreeqc` assert on what it says. All of them
want the source language. So the field stays, and it is now the recipe
rendered at `Locale::EN` — byte for byte what it was — with
`routing_phrase` beside it for the reader. `Provenance::routing_in(locale)`
is what a host calls.

Worth checking for and worth reporting when it is absent: **nothing
BRANCHES on the sentence.** #632 found `StructureOracle::apply` routing a
refusal by `why.contains("cannot name")`, where a reword would have
silently refiled a registry gap as a model boundary. The analogous read
here is `solve.rs` asking whether a solution was solved on an
ion-interaction model, and it reads `provenance.model` — a dataset's name
— not the prose. That is the shape to keep.

#### A list is a grammar, and eight sites had it as a string (#642)

`Slot::text(names.join(", "))` looks like a translated sentence with a
list in it. It is not: the separator is an English comma in the Rust, and
the final conjunction is missing entirely, so German read *a, b, c* where
it should read *a, b und c*. Eight sites had it — settled from the source
with a paren-matching scan, because the line-window scans that preceded it
gave five, six and eight and could not agree. `Slot::list`, `Slot::texts`
and `Slot::terms` exist now so the next call site is one line.

The ninth thing on I18N-10's list is `particles.rs`' `", and {n} more"`,
and it is not a `Slot` at all: `Census::render` takes a `Register` and no
`Locale`, and every caption in it is a literal. Converting the tail alone
would put *und 3 weitere* inside an English sentence, so the unit of work
is the function — and the lint reads its `locale.t` calls out of
`render.rs` alone, so that pass has to extend the lint too or its keys are
orphans in one direction and outside the denominator in the other.

## 3b. The command grammar — the words a learner TYPES

`zugeben v1 Wasser 100mL` runs. So does `messen v1 waage`, `erhitzen v1
10kJ auf Kerze` and `prüfen v1 kalkwasser`.

**The canonical script stays English, always.** A lesson (`lessons/*.lab`),
a saved session, the operator log, the corpus and the replay cache are all
English lines, on every machine, in every language. What a language gets is
an **alias layer read at parse time**: the line is rewritten into canonical
English before anything runs, and the canonical form is what the bench
echoes, logs, saves and exports. A session typed in German therefore
replays byte-identically on a bench that has never heard of German — and
two learners in two languages doing the same experiment produce the same
script.

That is the whole design, and everything else follows from it.

### Where the words live

In the language's own catalogue, nowhere else:

```toml
[script-verb]
add  = "zugeben, hinzufügen, dazugeben"
heat = "erhitzen, erwärmen, heizen"

[script-instrument]           # what `measure` may be pointed at
balance = "waage, masse, wägen"

[script-test]                 # `test v1 <name>`
limewater = "kalkwasser"

[script-source]               # `heat … on <flame>`
candle = "kerze"

[script-word]                 # the small joining words
until = "bis"

[script]
unknown-verb = "unbekannter Befehl '{word}' — die Bank kennt diese Verben: {verbs}"
```

The key is the canonical token; the value is that language's words for it.
**There is no German in `script.rs`** and there must not be: a match arm in
the parser is a language the next translator cannot add without a Rust
change.

Substance and glassware names are not written twice. `[species]` and
`[glassware]` already carry them for the sentences the bench composes, and
the parser reads those sections **backwards** — `Natriumchlorid` → `NaCl`,
`Reagenzglas` → `tube`. Material recipes are not in the catalogue at all:
`aliases.de` in the registry has always resolved (`add v1 Milch 100mL`
worked before any of this), and all that was added is the rewrite back to
`whole_milk` for the log.

### The three rules

1. **An alias means exactly one thing.** A word claimed by two canonical
   tokens is dropped rather than guessed at, so the bench cannot do one of
   two things depending on which section was read first.
2. **English wins.** A word that is already a token of this grammar is
   never taken over by a translation of something else. `magnet` and
   `voltmeter` are spelt the same in German, so the German spelling never
   registers — and never has to.
3. **One word.** An alias with a space in it can never be a single token of
   a command line, so it is skipped. This is why 34 of the 168 German
   species names are unreachable and their keys (`NaCl`, `AgNO3`) are not:
   German compounds, and English does not.

The rules are enforced where the index is built, not by review, and the
gate `a_canonical_line_is_never_rewritten` walks the whole verb inventory
in every shipped language to prove that no translation can change the
meaning of an English line.

### What is deliberately NOT translated

- **`above` / `below` in a redox endpoint.** Their German is `über` and
  `unter`, and `über` is already the preposition in `heat v1 40kJ über
  Kerze`. One word, two canonical meanings, is exactly what rule 1
  refuses — so an endpoint is written `until pe > 8`, with the symbol
  every language shares.
- **`magnet`, `voltmeter`, `courant`, `max`.** Identical in German; rule 2
  drops the alias, and nothing is lost.
- **Units.** `mL`, `g`, `mol`, `kJ`, `min`, `rpm`, `nm` are international
  and stay. So do vessel names (`v1`) and numbers — though the *prose* a
  German reads writes `1,5`, an identifier keeps its point.
- **Species keys and the codex's `KNOWN_…` lists.** Those are identity, not
  vocabulary. An alias never enters `script::VERBS` either: the inventory
  the affordance manifest is conformance-checked against is canonical.
- **`Ammoniumnitrat`.** German has one word for the pure substance
  `NH4NO3` and for the bottle `ammonium_nitrate`, which English tells apart
  by spelling them differently. Rule 1 applies across the shelf's two
  halves as well: the word is left alone and the bottle answers it, exactly
  as it did before.
- **Separable verbs.** `gib … zu` is how a German speaker would really say
  it, and it is two tokens with the command in between. The infinitive
  (`zugeben`) is what the table carries.

### What the learner sees

- The command bar offers the inventory as a `datalist`, composed by the
  engine from these same tables (`grammar` → `typed`), so a suggestion is
  always a line the parser takes — gated by a round trip through the
  rewrite, because a bar that suggests what the bench refuses is worse than
  a bar that suggests nothing.
- An unknown first word is refused **in the learner's language, naming the
  verbs that language has**. It is the one refusal that is about the
  vocabulary itself; the rest are about a number or a name and stay as they
  are.
- The echo in the feed is rewritten to the canonical line the bench
  understood, so the English form is learnable rather than hidden.

### The terminal, too

`kero repl --lang de` (or `KERO_LANG=de`) accepts the same German. The CLI
still *prints* English — its render path is English-only and that is a
separate job — so this is deliberately one half of a conversation: a
learner may type their own words at a terminal that answers in the source
language.

**`kero run --lang de FILE.lab` reads a file the same way**, and
`KERO_LANG` reaches it too. This was the one place the alias layer stopped:
`run` treated a `.lab` file as canonical English on purpose, so a learner
who could type `zugeben v1 Wasser 100mL` at the prompt could not put that
line in a file — `unknown command 'zugeben'`, from a bench that had just
accepted the word.

**English stays the default, and that default is load-bearing.** Every
shipped lesson, the corpus and the replay cache are canonical English
lines; none of them may change meaning because of an environment variable.
They do not, and not by luck: rule 2 above — a word the English grammar
already spends is never taken over by a translation — means an English
line is never rewritten in any language, so a shipped lesson run under
`--lang de` is the same run, step for step. That equality is a test.

**A file may also declare its own language**, on its first line, the way it
declares its register:

```
lang de
zugeben v1 Wasser 100mL
erhitzen v1 5kJ
```

This is the case a flag cannot cover. A lesson gets shared, and whoever
runs it next does not know what it was written in; `--lang` makes the
file's language a property of how it was invoked, and `lang de` makes it a
property of the file. It is accepted wherever `register` is — including the
REPL, where `lang de` switches the prompt's grammar mid-session — because
there is no reason for two rules. Unlike the flag, an unshipped tag here is
**refused by name** rather than falling back to English: `Locale::parse`
answering English is right for an environment variable someone else set and
wrong for a line an author wrote on purpose, where the alternative is
failing later, somewhere else, with a message about a verb.

What none of this changes is the transcript. The bench echoes, logs, saves
and exports the canonical English line however it was typed, so a German
`.lab` and its English twin print the same bytes.

## 6. The curiosity corpus — `tests/coverage/curiosity-v1/i18n/<code>.toml`

The capability explorer — "Was kann diese Werkbank beantworten?" — lists
five hundred reviewed questions with the material class and concept tags
under each. Its chrome was translated in #441 and its CONTENT was not, so
a German reader got a German dialog over five hundred English questions:
the one surface where the translation was invisible precisely because the
frame around it looked finished.

The German could not go in the corpus. `tests/coverage/curiosity-v1/` is a
**test artefact**: `kero coverage curiosity --check` joins a baseline to it
by `id`, and `CuriosityPrompt` is `deny_unknown_fields`, so a `question_de`
in a shard is a build failure rather than a translation. It lives beside
the corpus instead, in `i18n/<code>.toml`, keyed by the id the shard
already owns — the same file boundary as every other surface, and for the
same reason.

Three tables, because the explorer shows three kinds of authored English
and they have different key spaces:

| Table | Keyed by | Rows |
|-------|----------|-----:|
| `[question]` | prompt id | 500 |
| `[material_class]` | the English token | 186 |
| `[tag]` | the English token | 367 |

The glossaries are keyed by the English token rather than by prompt, so
`solubility` is translated once and reads the same under every question
that carries it. The 32 task identifiers among the tags — `CAP-5`,
`EXP-17`, `BRD-041` — are deliberately absent: they are names, not words,
and a translated identifier joins to nothing. So is `owning_task`, and so
are the outcome codes, which the interface labels through its own `t()`
keys.

`tools/curiosity-prose.py` validates and folds it in. It refuses a missing
id, a stale key, a translated identifier, a German question byte-identical
to its English (which is how an untranslated row survives a review that
only counts rows), and age or childhood wording — the corpus bands its
prompts by school age and the reader never sees that, so the band renders
through the level words the explorer maps. `tools/curiosity-index.py` then
writes the twins into `capabilities/index.json` as `question_de`,
`material_class_de` and `tags_de` siblings, and
`localiseCapability` in `web/app/src/lib/capabilities.ts` reads them with
a per-field fallback: corpus translation, then the shell's dictionary,
then the English itself. A field nobody has translated degrades on its
own, so a language can ship the questions before the glossaries.

The search box searches both languages. A German reader given a German
list has no reason to guess that the box wants English, and a search that
matched only the hidden source text would make the translation look
broken rather than the search.

## 4. Store and PWA surfaces

Whole duplicated files per locale: `manifest.de.webmanifest`,
`privacy.de.html`. This extends fine — a new language is a new file — but
by copy, so a change to the English original has to be repeated. Acceptable
for two short documents; worth revisiting at four languages.

`tools/test-pwa.mjs` checks that a German browser is served the German
manifest. It did not always: the `<link rel=manifest>` was written into the
page BEFORE the script that rewrote its href, and Chrome resolves the
manifest while parsing the head and keeps what it first saw. So German
readers installed the bench and got the English name and icons, while the
DOM said German and the check passed about two runs in three.

The script now creates the link itself, so only one href ever exists. The
lesson is the general one on this page: the first fix made the *check*
reliable and left the defect in place, because the check was asserting on
the DOM and the DOM was never the problem.

## German is longer than English, and the layout was built for English

Most of what a reader reported from an iPad was not a missing string. It
was a box sized for the English word:

| What they saw | Why |
|---|---|
| `Freigeschaltet` shrunk to nothing | 14 characters in a slot with room for ~11 |
| `Missionsset / verfügbar / Alles` unreadable | three German words across 370px at 0.62rem |
| `10 Entnal` | `10 Entnahmen übrig` is 18 characters in a 4.2rem column |
| stock count missing entirely | `Natriumchlorid` alone fills the row |

Two habits follow. Prefer the shorter German where both are honest —
`verfügbar` over `Freigeschaltet`, `noch 10` over `10 Entnahmen übrig` —
because a label that does not fit conveys nothing at all. And when a row
cannot hold everything, let it wrap rather than truncate: a learner needs
to read `Natron (Natriumhydrogencarbonat)` in full, and the count is what
can afford a second line.

Beware the flexbox trap here. `min-width: 0` lets a name column shrink,
and `overflow-wrap: anywhere` additionally shrinks its min-content width —
together they collapsed the column and broke every compound name into
`Natriu / mchlori / d`. That looked like a fix against the written bug
report, because the count *was* then visible.

`tools/shot.mjs` drives the built site in headless Chrome at a tablet

## Checking a translation

### The gate over the engine's inventories

`crates/kerotakis-core/tests/i18n_coverage.rs` asks the question no
coverage number answers: **can the engine emit a word German does not
have?** It walks the registries themselves — never a list beside them —
and fails naming each missing term:

| Inventory | Source of truth | Catalogue |
|---|---|---|
| species names | `species::registry()` | `species.*` |
| glassware | `vessel::VESSEL_KINDS` | `glassware.*` |
| instruments | `Instrument` variants → `render::instrument_name` | `instrument.*` |
| phases, phase-change verbs | `Phase` variants → `render::phase_key`, `phase_change_verb` | `phase.*`, `verb.*` |
| severities | `Severity` variants | `severity.*` |
| enzyme families | `EnzymeFamily` variants | `enzyme-family.*` |
| spill sites | `SpillDestination` variants → `render::spill_site_name` | `spill-site.*` |
| appearance words | `SpeciesData.appearance` | `appearance.*` |
| flame colours | `SpeciesData.flame_colour` | `flame.*` |
| events | `Event` serde variant names | `event.*.lv1` |
| relations | `relations::RELATIONS` | `purpose_de` / `validity_de` / `source_de` |
| hazardous vapours | `senses::ODORS` | `hazard_vapour.*` (in `hazard_locale.rs`) |
| incompatibilities | `INCOMPATIBLE` | `hazard.*`, `real_world.*` (in `kerotakis-safety`, which owns the private table) |

The enums are enumerated by deserialising a tag no variant claims and
reading the variants out of serde's own error, so adding a variant
extends the gate without anyone remembering to. `the_variant_reader_is_
not_silently_reading_nothing` guards that trick: if serde reworded the
message the reader would return an empty list and the gate would pass by
checking nothing, which is the quietest way for a gate to die.

Three inventories are consciously **out of scope**, and the test says so
in its header: refusal reasons that interpolate a value (the event
carries a finished sentence, so there is no key to enumerate — a wire
change first); `script::VERBS`, which is command grammar a user TYPES
rather than prose anyone reads; and `Appearance.words`, prose assembled
in `appearance.rs` rather than drawn from a table. It was four until
I18N-13 took the LV2/LV3 evidence lines off the list.

Its first run found **80 missing terms**, in four different shapes of
failure — while `engine-locale-lint.py` reported 100% coverage throughout,
truthfully, because it measures the keys that exist rather than the words
the engine can produce:

- **17 species** added to the registry since the last translation pass —
  sucrose, bromoethane, the iron hydroxides, the whole tert-butyl bromide
  hydrolysis set. The *interface* had German for every one of them:
  `i18n.test.ts` walks `registry-source-v1.json` and fails without it. The
  engine had no equivalent, so the same substance was `Saccharose` on the
  shelf and `sucrose` in the journal line about it — two dictionaries, one
  gated and one not, which is the whole argument for this file.
- **48 appearance words** — `pale blue`, `white crystalline powder` —
  which had no catalogue section at all: `render.rs` dropped
  `SpeciesData.appearance` straight into the translated sentence, so a
  German reader was told *"Ein white Feststoff erscheint am Boden"*. The
  colour is what that sentence is FOR.
- **2 glassware kinds.** Nothing was missing from the file; the file was
  keyed on words the engine never emits. `VESSEL_KINDS` holds the short
  labels `tube` and `cylinder`, and the catalogue had only `test tube`
  and `measuring cylinder` beside them.
- **13 event sentences**, covering 12 variants whose LV1 was still inside
  a bare `format!`. Those were not untranslated but untranslatABLE, which
  is why the check starts from the `Event` enum and not from the file.

  Seven were the fermentation, emulsion, curdling, surface-colour and
  material-layer events. The other five — `SpillCreated`,
  `ContainerBroken`, `CollisionWithstood`, `SpillRecovered`,
  `SpillHazard` — **were merged to main while this gate was being
  written, and it caught them on the rebase, the same afternoon.** That
  is the whole case for the gate in one paragraph: a feature landed
  English-only, every existing check stayed green, and the only thing
  that noticed was a test that walks the enum. `SpillHazard` also had no
  arm in `localize_event`, so its two safety sentences reached the shell
  in English — the identical defect I18N.md records for `HazardWarning`,
  recurring on the next event to carry a hazard.

Fixing them needed four `render.rs` changes as well as the German, because
a term the renderer never looks up cannot be translated by adding it to a
file: `appearance` gained a lookup, `Ignited` began looking its flame
colour up the way `FlameTest` already did, seven event arms moved from
`format!` to `locale.fill`, and `Dissolved`, `Inert` and `Consumed` began
translating the species name in their LV1 sentence — those three said
*"Das sucrose löst sich auf"* while `Added` and `Ground` beside them got
it right.

The glassware case is the one to remember. Every other gate here asks
whether the catalogue has an entry; that one failed because the entry it
had was for a word nothing says.

```sh
python3 tools/codex-locale-lint.py --check   # catalogue: coverage per language, stale keys, glossary
python3 tools/engine-locale-lint.py --check  # engine: coverage, keys shared by two sentences
python3 tools/i18n-holes-lint.py --check     # every {placeholder} has something to fill it
python3 tools/i18n-surface-lint.py --check   # nothing filters or sorts text it does not render
python3 tools/i18n-slug-lint.py --check      # every codex slug the shell de-slugs has a German word
node tools/test-i18n-render.mjs <payload>    # what a browser actually shows
```

All five lints run in `tools/preflight.sh`, so CI enforces them. They
answer different questions and none subsumes another: the render test can
see that German reaches the screen but not that two sentences share a key;
the holes lint can see an unfilled placeholder that nothing else notices,
because `fill` leaves it as written and the code is valid Rust.

The slug lint is the youngest and covers the seam I18N-2 named: a concept
node and an experiment name have no label field anywhere, so the component
de-slugs the identifier — `activation-energy` → `t("activation energy")` —
and the German lands in the interface dictionary rather than in the
catalogue that owns the entry. Nothing joined the two ends, so a codex
entry could add a concept and the map would render it in English inside a
German screen, failing nothing. It derives the key set from the same codex
fields the components read, and pins its own assumption to `tSlug`'s
source, so a change to the de-slugging fails the lint instead of quietly
invalidating it.

The lint also enforces a small glossary, because the first translation pass
rendered *bench* as **Werkbank** where the interface says **Labor** — not
wrong in isolation, but it makes the app read as two translations stitched
together. Note that the physical surface is a **Labortisch**; where prose
contrasts the simulated bench with a real one, both words are needed and
collapsing them destroys the contrast.

## The codex's own words

The catalogue names 103 experiments and 157 concepts as slugs, and neither
has a German anywhere but `messages` in the bundle — no component writes
either down, so `i18n.test.ts`, which scans source for literal `t("…")`
arguments, cannot see them at all. `codexTerms.test.ts` walks the exported
catalogue instead and requires a German entry for every id and every
concept, so an experiment added to the codex fails a test rather than
shipping its English slug.

Concept labels are **Fachbegriffe, not prose**: the word a German
curriculum uses, not a translation of the English. Where two German terms
genuinely compete the school-curriculum one wins, and the alternative is
worth recording because the loser is usually the one a university text
would have chosen:

| Slug | Chosen | Also current |
|---|---|---|
| `common-ion-effect` | Gleichioneneffekt | Effekt des gleichionigen Zusatzes |
| `surface-area` | Zerteilungsgrad | Oberfläche |
| `kinetic-barrier` | Kinetische Hemmung | kinetische Barriere |
| `amphiprotic-ions` | Ampholyte | amphiprotische Ionen |
| `evaporation` | Eindampfen | Verdunstung, Abdampfen |
| `limiting-reagent` | Limitierendes Reagenz | Unterschusskomponente |
| `polyprotic-acids` | Mehrwertige Säuren | mehrprotonige Säuren |
| `conjugate-base` | Korrespondierende Base | konjugierte Base |
| `ksp` | K_L (Löslichkeitsprodukt) | Ksp |
| `fair-test` | Fairer Test | Variablenkontrolle |

`evaporation` is a glossary case rather than a taste one. The engine
renders the operation as *verdampfen* into an **Abdampfschale**, so the
concept beside it cannot be *Verdunstung* — that is the word for what
happens below boiling, and the two together read as two different
processes.

## The three surfaces that held a locale and did not use it (2026-09-20)

Reported together, fixed together, because they are one defect wearing
three coats: **a host knew the reader's language and did not pass it on.**
Not one of them was a missing translation. Every German string involved
already existed in a catalogue; none of the three was ever looked up.

That is the shape worth remembering. `t()` and `locale.t()` both fall back
to the key, and the key IS the English source, so **a missing lookup and a
missing row look identical on screen** — and neither looks broken.

### 1. The terminal REPL

```
kero> add v1 water 100mL
  v1: +5.5343 mol water        ← the REPL, holding a German locale
  v1 +5,5343 mol Wasser        ← the GUI, same command
```

`crates/kerotakis-cli/src/main.rs` carried `self.locale`, used it for
errors, for `explain` and for the particle census — and then called

```rust
render_events(&events, self.register)
```

`render_events` is the English-only wrapper: `render.rs:615` is literally
`render_events_in(events, register, Locale::EN)`. `render_vessel` was the
same one function along, and `render_ionic_for` was passed `Locale::EN` by
hand. The decimal separator rides the same locale through
`Locale::number`, which is why `5.5343` and the English word were one bug
and not two.

Two smaller welds went with it: `particles`' header was a bare `println!`
above a caption that had gone through the catalogue since September, and
`Event::Added` at **lv3** was still a bare `format!` while lv1 and lv2
beside it were catalogued — the one register of `add` no translation could
reach.

**`--lang` was answering two questions with one field**, and now answers
them with two:

| field | meaning | set by |
|---|---|---|
| `Session.locale` | the language the person **reads** in | `--lang`, `KERO_LANG`, `lang de` typed at the prompt |
| `Session.script_locale` | the language arriving lines are **typed** in | all of those, **plus** a `lang de` directive on a file's first line |

A `lang de` *directive* describes the FILE, not whoever runs it, so a
shipped German-authored lesson still reads back canonical English to an
English reader who was handed it. A `--lang de` *invocation* is a
statement about a person.

`run_lang.rs` had pinned the canonical-transcript invariant on stdout
prose, and it only held there **because of this bug**. It moved to
`--json`, which is where the contract actually lives: structure, no prose.

### 2. The periodic table's `benötigt:` list

`PeriodicTable.svelte` rendered

```svelte
{t("needs: {materials}", { materials: route.requiredShelfKeys.join(", ") })}
```

The label went through `t()`. The items did not — they are raw engine keys
— so a German reader got `benötigt: water, baking_soda` two paragraphs
below the same bottles correctly listed as *Wasser*.

**The key was never the thing to translate.** De-slugging `apple_juice`
into `"apple juice"` gives a phrase no catalogue has, and adding a row for
it would have duplicated `apple juice surrogate` → *Apfelsaft*, which
`de.json` already carries. The NAME is what the dictionary is keyed on, so
the key is resolved against the shelf first — and every key there is on
the shelf by construction, because `contentRoutesForElement` only offers a
route whose `requiredShelfKeys.every(k => shelfKeys.has(k))`.

**Zero catalogue rows were added.** The translations were all already
there.

### 3. The console page's link to the bench app

`web/index.html` is the one page in the repo with its own inline
dictionary, because it is hand-written and has no build step to reach
`web/app/src/locales/`. Both German rows for

```html
<p><a href="app/">→ the bench app</a> — same
  engine, drawn glassware</p>
```

existed. Neither was reached, for **two independent reasons**, and fixing
either alone still leaves a German reader reading English:

1. The DOM sweep visits the *direct* text children of the elements it
   selects. `<a>` was not selected, so the anchor's text was invisible to
   it however many rows the dictionary held.
2. The `<p>`'s own text node carries the source file's line break, so it
   really reads `"— same\n      engine, drawn glassware"`. `tr()` is an
   exact match with a silent fallback.

The sweep now names `#side p a` (and `header #status`, a third orphan the
lint found on its first run) and collapses whitespace before looking up.

### The lints that could not see any of it

All three surfaces were invisible to every instrument, which is the #505
shape once more: *a surface invisible to the instrument that counts
surfaces does not exist.*

- **`tools/console-locale-lint.py` is new.** Nothing in `tools/` read
  `web/index.html` at all. It asks the question `engine-locale-lint`
  already asks of the engine catalogue — **is every translated string
  reachable?** — because a row nobody looks up is a translation that was
  written and thrown away. It feature-detects whether the page's sweep
  normalises whitespace, so it models the lookup the page actually
  performs rather than the one it wishes were there. It deliberately does
  NOT ask the mirror question: `PHREEQC`, `github.com/CrispStrobe/kerotakis`
  and `inspect v1` are swept, have no German row, and are correct. A lint
  that cries wolf is one people learn to skip.
- **`tools/i18n-surface-lint.py` gained rule 3**: a list joined INTO a
  translated sentence must itself be translated. It recognises a
  translator by convention — `t`, or `t` followed by a capital (`tSlug`,
  `tEngine`, `tShelfKey`) — called *or* passed by reference, since
  `.map(tSlug)` is the commoner spelling here. The first draft read only
  the call form and reported all five correct sites.
- **The CLI is guarded at the source**, because the bug compiled, ran and
  printed perfectly good English. `cli_locale.rs` asserts that no
  `Locale::EN` appears in `crates/kerotakis-cli/src/` without a stated
  reader, and that the CLI calls none of the English-only render wrappers.

### Why the wrappers were not deleted

A previous pass deleted `plain_name` and `Kind::describe` once every caller
took a locale. `render_events`, `render_vessel`, `render_event` and
`render_ionic` are **not** in that position: they still have callers, in
`kerotakis-core/tests/`, `kerotakis-phreeqc/tests/` and
`kerotakis-cea/tests/`, which assert on English prose *on purpose*.
Deleting them would turn a locale question into a test rewrite. What was
missing was not a deletion but a rule, so there is a test instead of one.

### The test that had to exist

A golden string would not have caught the REPL bug, because **the English
golden string was correct**. The guard is a pair: the same script run in
two languages must agree on every digit — separators discarded, so
`5.5343` and `5,5343` both reduce to `55343` — and differ on every line
carrying a word a translator owns. That property survives someone
improving a translation, and a fourth language inherits it without a new
test. One golden string sits beside it, because the pair test cannot tell
German from French.

### The standing exception

`web/index.html`, `web/manifest.de.webmanifest` and `web/privacy.de.html`
are whole-file or inline siblings, not catalogue rows, so **French there
is still a file each** (step 5 of "Adding a language"). Everything else
holds: `crates/kerotakis-core/i18n/fr.toml`,
`web/app/src/locales/fr.json`, `lessons/prose/fr.toml`, no code.

## How this went wrong, six times

Worth reading before trusting any coverage number.

Every translation path falls back per string, by design. That means a
string the code never asks for is indistinguishable from a string nobody
translated: both render English. On 2026-08-27 the catalogue reached
1008/1008 by the lint, the browser test passed green, and **not one word of
it reached a learner** — for two independent reasons in two layers.

1. Every render site passed the *English* value through `t()`, the
   interface dictionary, which will never hold a three-sentence paragraph
   as a key. So `t()` returned its argument unchanged.
2. The web app does not read `codex/*.toml`. It reads JSON exported by
   `kerotakis-codex`, and only `registers` survived that trip because a map
   carries unknown keys through serde. Every typed field — `question_de`,
   `options_de`, `reveals_de` — was deserialised into nothing and never
   re-emitted.

The golden snapshot had said so precisely: it gained exactly 393 keys,
which is 131 entries × 3 registers and nothing else. The number was the
message.

And the browser test passed throughout, because it checked the map and the
toolbox — the two places that had just been fixed. **A test that only looks
where you already worked is a test that agrees with you.** It also treated
a section it could not reach as a section that passed; it now fails
instead.

So: a coverage count is evidence that strings exist, never that anyone sees
them. Only `tools/test-i18n-render.mjs` answers the second question, and
only for the screens it actually opens.

Three more surfaced the same day, after that was written and after the
translation was believed finished. All four gates were green over every one
of them.

3. **The catalogue searched English while displaying German.** Typing
   `Säure` into the experiment filter returned "nothing matches" with the
   German word visible in the list behind it. An empty result set looks
   like an answer, so nothing about it reads as broken. The concept map and
   the shelf had the same shape in their sorting: German on screen, English
   in the comparator, so the list came out in an order with no visible
   logic. `tools/i18n-surface-lint.py` now enforces that a display surface
   filters and sorts what it renders.

4. **A French sidecar was accepted and half-discarded.** `Registers` is a
   map, so `lv1_fr` travelled; the prose fields are named `summary_de`,
   `question_de` and so on, so serde dropped the French with no error. This
   page had claimed adding a language was "No code change" — it was not,
   and could not have been caught in German, the language every field is
   named after. `tests/french_probe.rs` now writes an `i18n/fr.toml` into a
   temp directory and requires the French in the exported JSON.

5. **German installs got the English manifest.** The link tag was written
   before the script that rewrote it, and Chrome keeps the manifest it
   resolved while parsing. The gate that should have caught this had been
   "fixed" that morning by making it *wait* — which made the DOM assertion
   reliable and left the defect untouched, one line below.

The pattern is the same in all five: **the failure mode is silence.** A
missing translation renders English, a dropped field renders English, an
empty search result renders as an answer, an English app icon renders as a
design choice. None of them fail anything.

So the only defences that work here are the ones that walk a source of
truth and compare — `hazardous_vapours_are_all_translated` over
`senses::ODORS`, the surface lint over what a component renders, the French
probe over a real directory. A test written by looking at the code you just
changed will agree with you. Three of these five were found only because
someone asked a question the tests were not asking: *what about French?*

6. **2026-09-20 — three surfaces held the reader's language and did not
   pass it on.** The terminal REPL rendered English while carrying a
   German locale; the periodic table translated a list's LABEL and not its
   items; the console page's own dictionary had two rows for a sentence it
   never looked up. Not one was a missing translation — every German
   string involved already existed. The lesson is the one above, stated
   from the other side: because a fallback returns the key, and the key is
   the English source, **a call site that never asks is indistinguishable
   from a catalogue that cannot answer.** Counting rows finds the second
   and never the first. Three of the four guards added that day read
   SOURCE — call sites, selectors, text nodes — for exactly that reason.
