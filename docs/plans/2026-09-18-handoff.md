## The standing constraint this work is under

The project owner's requirement is that **nothing here may claim empirical
accuracy it does not have.** Every new measurement, fit and transport test
added in this pass is a *software* test. None is evidence that the chemistry
matches the world. That distinction is load-bearing and is repeated at each
relevant seam rather than stated once here.

## What was built

### 1. Irreversible protein heat history (`protein.rs`, `vessel.rs`)

`observe` previously derived the denatured fraction from the *current*
temperature, so a sample that was boiled and then cooled reported itself
native again. `UnresolvedMaterialPortion` now carries a defaulted persisted
`protein_denatured_fraction`, updated after physical steps by
`record_heat_history` and read by `observe` as `max(current, history)`.

Two boundaries are deliberate and documented in the code:

- It is a **qualitative irreversible envelope** built from the existing
  temperature thresholds — *not a measured time-dependent rate law*. No
  kinetic constant was invented.
- Old snapshots/portions default to raw (the `#[serde(default)]` value), and
  freshly added raw material does not inherit a cooked portion's history.

### 2. Calibrated persisted measurement layer (`measurement.rs`, MEAS-001)

`MeasurementDevice` wraps an existing ideal `InstrumentContract` with:

- two-point affine calibration (degenerate spans refused);
- declared resolution, error width, and first-order response lag;
- an **indexed** noise stream (sample *n* from a generator seeded by
  `(device seed, n)`), so records replay bit-identically after save/load with
  no hidden RNG state, and a failed reading consumes nothing;
- range (`in_range`) kept strictly separate from chemical-model validity —
  the latter is the caller's to report, not this layer's.

`from_state` revalidates every persisted field, so a corrupt/hand-edited
snapshot is refused rather than silently adopted.
`MeasurementRecord` carries no sample composition and no instrument internals.

### 3. Bounded two-parameter inference (`inference.rs`, INF-001)

Grid search over two parameters per declared hypothesis, with:

- chi-squared against declared per-observation sigma;
- an **ambiguity** list of alternative parameter pairs that fit comparably;
- `identifiable`, which is a *grid heuristic*, explicitly not a structural
  identifiability proof nor a confidence contour.

Three defects were found and fixed by test during this pass: repeated
observations of one observable previously contributed only once (the
`.find()` matched one prediction and abandoned the rest), a missing or
non-finite prediction previously scored as zero error, and publicly
constructible invalid `Observation`s (non-finite value, non-positive sigma)
were accepted on the public path.

### 4. Unknown-water activity (`kerotakis-phreeqc/tests/unknown_water.rs`)

A real PHREEQC bench distinguishes NaCl from sucrose via pH + conductivity,
and refuses to discriminate under wide-sigma data. Forward models are
tabulated **once** through one shared engine (`TabulatedHypothesis::build`) —
per-grid-point engine construction was the original bug and produced silently
empty predictions that scored chi-squared 0 for every hypothesis.

The learner side holds only serializable observations, no composition.
Grid starts at a small positive concentration: zero moles `Add` is refused.

### 5. Bound-inventory coupling fix (`delta.rs`, `orchestrator.rs`)

This is the ARCH-011 seam the coupling review pointed at, and it was a **real
latent defect, not a hypothetical**. `diff_vessels` diffed only
`vessel.contents`, so a rung that moved matter onto a sorbent had that move
invisible to the delta while the conserved-element audit still saw the matter
leave. The result was a `conservation violation` and a rolled-back commit:
adsorption silently did nothing on the orchestrator path.

`StateDelta` gained `adsorbed_changes: Vec<AdsorbedDelta>`, with matching
`with_adsorbed`, `validate` (cumulative per-prefix overdraft detection
matching apply order, non-finite refusal), `apply`, `is_empty`, and
inventory scaling. `diff_vessels` now diffs the bound ledger in both
directions.

### 6. Column breakthrough characterisation (`column_breakthrough.rs`, COLUMN-001)

Matter closes exactly over a whole open-column run at every Courant fraction
tested (1.0, 0.5, 0.25, 0.125). At Courant 1 the update is exact plug flow.
The dispersion test was rewritten after analysis showed the first version's
premise was geometrically wrong: at one displaced column volume the smeared
front is *centred on the outlet*, so absolute effluent grows with cell count.
The implemented invariant holds the total column volume and inlet
concentration fixed across refinements and asserts the **breakthrough
fraction** shrinks monotonically.

### 7. Documentation correction (`validation/README.md`)

The README still described the pre-2026-09-15 audit finding (`wired = false`
on the molar masses). It now points at
[`docs/one-value-for-the-solvent.md`](../docs/one-value-for-the-solvent.md),
records that the three molar-mass records are `wired = true`, keeps the
arithmetic reason NaCl and sucrose have empty `reaches` lists, and is explicit
that **traceability was bought and a band was not**: fusion's uncertainty is
`unestablished` (a difference of two fitted NASA polynomials) and
vaporisation's source declines to estimate accuracy (`not_reported`).

   work, check the `wasm32` target explicitly.

   (`tauri.conf.json` in the preserved commit, and nothing else in this pass)
   were not exercised. The measurement/inference layers are core-crate API
   with no UI wired to them yet — see S3, which is exactly the work of wiring
   them to a learner-facing surface.
4. **Nothing here is calibrated against the world.** Every test above is a
   software test. The inference tests in particular are synthetic, and
   `unknown_water.rs` discriminates two hypotheses using the project's own
   PHREEQC dataset — reproducing a curated engine's answer is not independent
   evidence of the chemistry.

## Not done: the scoped remainder

These are the larger items from the coupling/measurement review. None is
started. They are ordered as the review argued, highest leverage first.

### S1. Explicit coupling contracts between models

Today, solver order encodes dependency (`kerotakis-stack/src/lib.rs` orders
corrosion and adsorption after aqueous chemistry, with comments explaining
why). The step beyond that is to let a model *declare*:

- state it reads and state it changes;
- processes/inventories it owns (so two models cannot apply the same
  reaction or transfer twice);
- equilibrium versus finite-rate assumptions;
- parameter and standard-state conventions (activity, concentration,
  thermodynamic reference) so incompatible ones cannot be silently combined;
- coupling/convergence requirements (when one pass suffices, when iteration
  is required).

Extend the existing applicability reports, validity bounds, model-route
classifications and `StateDelta` rather than building a parallel framework.
The bound-inventory fix above is the first concrete instance of this class of
bug and is a good template for what a "declared ownership" check would catch.

### S2. Generalise `CellChain` into a compartment/interface network

`CellChain` already does first-order upwind transport plus local equilibrium
with rollback. Its documented restrictions are uniform cells and a constrained
transported inventory. The expansion is a reusable network — reservoirs,
columns, membranes, recirculation, gas–liquid contact, electrodes — with most
nodes well mixed and only selected components spatially resolved. The
acceptance bar is conservation including boundary flows, time-step and spatial
convergence, and reproduction of an independent experiment.

### S3. Separate physical state from experimental knowledge

The measurement layer is the foundation; the missing half is that the
simulator may know an unknown sample's composition while the notebook and
identification tools must not acquire it automatically. Instrument response
should be `y = H(x, instrument, calibration) + error` with resolution, lag,
drift, background, detection limits, saturation, sample consumption and
calibration uncertainty. Error must not be a blanket Gaussian: censoring below
a detection limit and correlated baseline drift are different experiments.

### S4. Inference beyond a single fit

Multi-parameter estimation with correlations and explicit units;
identifiability reporting (when parameter combinations are indistinguishable
from the available data); competing-model comparison; and experimental design
(suggesting the measurement that best separates remaining hypotheses). A
valuable lesson to build toward: *the meter is precise but the inferred
concentration is uncertain because the calibration or chemical model is
uncertain* — instrument error, uncertain parameters, and model inadequacy
should stay separate quantities.

### S5. Analytical instruments (NMR, diffraction, IR/Raman)

Not started, and deliberately last. The compelling activity is a blind
identification constrained by several measurements of one conserved sample,
not a spectrum browser. Candidate references are recorded in the review:
`sametz/nmrsim` (MIT) for a bounded NMR forward model, `pymatgen` (MIT) for
powder diffraction at authoring time, PySCF (Apache-2.0) for build-time
vibrational packs. The hard line: simulating a spectrum *from* shifts and
couplings is not predicting those parameters for an arbitrary molecule, and a
crystal structure does not establish thermodynamic stability, a transformation
pathway, or a formation rate. A missing band must stay missing, not become
zero absorbance.

### S6. History-dependent materials beyond proteins

`protein.rs` was the first instance (now fixed). `gel.rs` disclaims measured
modulus and relaxation time; emulsions have no droplet-size state;
precipitates have no nucleation/growth. The defining test to aim at: *can two
samples with the same final temperature and bulk composition behave
differently because of how they got there?* Prefer a few interpretable kinetic
states or a small population-balance model over molecular dynamics. The
difficult part is not more state variables — it is evidence justifying their
evolution equations.

### S7. Open parameter and validation pipeline

The accuracy corpus (`validation/README.md`) is one family with six anchored
rows over two quantities, with `transcription = no` on every source. It is
candid and it is a backlog, not a gate. The pipeline worth building:
rights-reviewed measurements → normalised conditions and units → parameter
estimation → independent holdout tests → uncertainty and validity assessment →
versioned runtime pack. A pack must answer where values originated and under
what redistribution rights, which observations fitted and which were held out,
under what conditions the model was tested, which parameters are correlated,
and whether the running solver actually consumes this version.
**Success is measured in independently validated quantities and domains, not
reaction count or passing examples.** Synthetic data generated by the same
model validates inference *software* only.

### S8. Licence boundaries, if any external code is ever vendored

`deny.toml` carries a permissive allowlist for Rust crates. Two candidates the
review flagged as **not acceptable unmodified**: libRoadRunner (Apache-2.0
itself but uses LGPL-2.1 libSBML) and OpenMM (mixed MIT/LGPL). OpenPNM
declares MIT but its dependency manifest includes platform-dependent
`pypardiso`. Code rights and data rights are separate questions: a
permissively licensed importer does not grant redistribution rights over what
it imports, and fitting a parameter set does not resolve restrictions on the
source material.

## The flagship experiment worth building first

An **unknown-water investigation**: the learner receives an unknown sample,
calibrates instruments, gathers pH/conductivity/titration observations, fits
competing composition hypotheses, chooses the measurement that distinguishes
them, passes the sample through a modelled treatment column, and compares a
predicted breakthrough curve against observations.

Everything in this pass is infrastructure toward that single activity, which
is also the best integration test available: it exercises shared physical
state, uncertainty, inference, transport, existing chemistry and model
limitations at once, and exposes integration mistakes that another hundred
isolated reaction examples would not.
