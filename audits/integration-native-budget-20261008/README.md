# Bounded native phase-budget integration

This main-based integration freezes 50 existing mixed-crystal boundary contracts before porting production changes. [The source map](contracts-freeze.json) binds each byte-identical copied test file and its donor snapshot. Original fixtures remain beside separately identified complete-column and closed-boundary adaptations; [preserved receipts](preserved/) explain those corrections and retain the earlier diagnostic outcomes.

The intended port covers finite typed phase readback, explicit Ca/Sr/C owner budgets, bounded exclusive aqueous reconciliation, raw mandatory-column validation, and reviewed external gas-phase validation. It uses the existing public Amount primitive and typed crystal API.

Hosted baseline and repair execution against this main-based revision are pending. Donor branch results do not establish main-based compatibility. Native extensive normalization, general trace retention, thermal iteration/characterization, KNO3 heat data, temperature uncertainty and broader stack transaction changes are separate integration work.

## Production port scope

[The production hunk map](production-port.json) records the donor contexts and final file hashes. The port adds the checked reconciliation helpers, validates raw selected solvent/element/state/component amounts, and replaces the old unconditional mixed-crystal correction. The core typed crystal validity check additionally rejects nonfinite aggregate moles or mass. Other production functions retain their main-based implementations.

The bounded domain is one reviewed Ca/Sr carbonate mixed crystal, reviewed pure-phase owners and gas boundaries. Closed calcium and strontium budgets remain checked across an external carbon boundary. Mixed surface/exchange co-ownership and unexplained inclusive aqueous totals refuse. Separate native, selected-output and arithmetic acceptance ceilings are implementation bounds, not validated chemical accuracy. An arithmetic-only trace discrepancy retains its raw witness.

No public Rust fields or event variants are added. Existing `SolveError::NotConverged` and solver failure events carry stricter refusals, which can affect failure diagnostics and expectations for previously accepted unsupported states. Ordinary successful outputs, native engine behavior and existing goldens still require hosted checks. This stage does not claim microscopic native support or broader transaction coverage from donor evidence.
