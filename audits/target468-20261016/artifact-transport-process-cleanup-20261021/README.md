# Bound artifact transports to their owned process group

The previous download helper killed only its direct process, and only while that process was alive. A descendant could retain stdout after its leader exited, keeping collection waiting until the deadline and surviving the failure cleanup. This is a demonstrated source/resource-management gap, not an observed chemistry or production failure.

`receive` now starts a new session and cleans its owned group with TERM, a bounded wait and unconditional KILL, even after leader exit. It reaps the direct process. Successful transport also cleans leftover owned descendants before publishing verified bytes. Selector/pipe cleanup is bounded and preserves the original exception; secondary cleanup failures become notes on that primary failure. The helper never signals the caller's group or an unrelated sentinel. Inactive orphan zombies are distinguished from running survivors; this does not claim that it can reap another parent's child.

The actual partial file and stderr remain retained on refusal. Size/deadline/nonzero/checksum refusals, exclusive creation, complete SHA/readback and no-retry behavior are unchanged. `publish` and `digest` are AST-identical to the accepted helper. The delivery preparation preserves all13 prior source/input files and the original API11 requests, archive verifier, isolation and concurrency controls. Both default entry points remain no-op without explicit reviewed activation. Earlier preparations and currently running collectors were not changed.

Parent independently ran10 real tiny local Linux subprocess controls. They cover authenticated transfer, size/checksum/nonzero/setup errors, live-leader and already-exited-leader inherited stdout, TERM-ignoring descendants, cleanup after success, an unrelated live sentinel and a real asynchronous SIGUSR1 cleanup error that must retain the original size assertion and cleanup note. There are no mocked cleanup results, engine executions, network requests or fabricated chemistry rows. `PARENT-REVIEW.json` and both raw streams preserve the invocation. Run `python3 -B test_artifact_spool_processes.py` on Linux to reproduce.
